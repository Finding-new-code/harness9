# ADR-002: Pydantic v2 Production Contracts Architecture

**Status:** ACCEPTED  
**Date:** 2026-08-31  
**Deciders:** Head of Engineering, Architecture Team  
**Scope:** Production Contracts (`src/models/contracts.py`)  

---

## 1. Context & Problem Statement

Autonomous multi-agent video production pipelines pass complex structured data across numerous subsystems (researchers, scriptwriters, voice directors, asset freezers, renderers, and quality benchmarks). In earlier prototypes, data was exchanged as unstructured Python dictionaries. This caused:
1. **Silent Schema Drift**: Missing keys or renamed attributes caused downstream render failures hours into a pipeline run.
2. **Type Coercion Bugs**: Numerical strings being passed to DSP filters or timing calculators causing runtime type exceptions.
3. **Lossy Serialization**: Inability to seamlessly serialize and deserialize state models to both machine-readable JSON and human-readable YAML without custom encoders.

---

## 2. Decision & Architecture

We decided to standardize all 17 inter-stage data exchanges on **Pydantic v2 schemas** inheriting from a shared base model `H9BaseModel` in `src/models/contracts.py`.

### 2.1 The 17 Core Contracts
1. `CreatorProfile`: Brand Constitution, voice preferences, and negative rules.
2. `ContentBrief`: Initial project goal, duration, aspect ratio, and audience.
3. `ResearchPlan`: Target claim counts and search queries.
4. `ResearchDossier`: Consolidated claims, sources, and statistics.
5. `SourceRecord`: Citation provenance and domain authority.
6. `ClaimRecord`: Verified factual claims and confidence scores.
7. `EditorialAngle`: Evaluated narrative angle and 9-dimension scorecard.
8. `ContentOutline`: 4-act narrative time structure.
9. `Script`: Scene dialogue, visual descriptions, and word counts.
10. `ScriptBeat`: Micro-timing and asset requirements.
11. `AssetRequirement`: Visual queries and aspect ratio needs.
12. `AssetRecord`: Frozen asset metadata with SHA-256 and dHash.
13. `EvaluationReport`: ContentBench quality layer audit report.
14. `RenderArtifact`: Final MP4 video specs and duration.
15. `PublishPackage`: Multi-platform distribution bundle.
16. `AnalyticsSnapshot`: Post-publish audience retention telemetry.
17. `LearningCandidate`: Distilled learning rule for creator DNA evolution.

### 2.2 Shared `H9BaseModel` Capabilities
- **Dual Serialization**: Native `.to_json()` and `.to_yaml()` methods.
- **Atomic Disk Persistence**: `.save(output_dir, base_name)` writes both `.json` and `.yaml` atomically.
- **Dict Compatibility**: Supports subscripting `model["key"]` and `.get("key", default)` for backwards compatibility with legacy dictionary-based consumers.

---

## 3. Consequences & Trade-Offs

### Positive Consequences
- **Zero Runtime Schema Failures**: Strict type validation prevents corrupt data from propagating downstream.
- **Clean Tool Interoperability**: Pydantic models automatically generate JSON schemas for Hermes Agent tool calling.
- **Human Readability**: YAML export allows creators to directly inspect and edit briefs and scripts.

### Negative Consequences / Mitigations
- **Dependency on Pydantic v2**: Requires `pydantic>=2.0`.
  - *Mitigation*: Pydantic v2 is modern, extremely fast (compiled in Rust), and standard in modern Python AI ecosystems.
